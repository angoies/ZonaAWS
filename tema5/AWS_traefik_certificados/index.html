    Traefik y https¶

    1. Escenario inicial¶

    1.1. EC2 en AWS¶

    Para el desarrollo de la práctica se partirá de:

    • una instancia EC2 en AWS con docker ya instalado (debe poder acceder a la instancia usando ssh).
    • una IP elástica asociada a la instancia (para poder asociarla a un dominio DNS).

    1.2. Dominio DNS¶

    Necesita un dominio a gestionar para asociar nombres de host a la IP elástica usada en la instancia EC2 de AWS. Tiene entre otras las siguientes opciones gratuitas:

    • Dynu y su servicio DDNS
    • Duckdns
    • otras en este listado
    • el dominio .tech que es gratuito usando el Developer Pack Student de GitHub https://get.tech/github-student-developer-pack. En este caso tenga en cuenta que:
      1. Importante: debe realizar el alta desde esta dirección: https://get.tech/github-student-developer-pack
      2. Buscar y seleccionar un dominio libre
      3. Al ordenar el pago hay un botón para identificarse con su cuenta de GitHub (la que esté asociada a los beneficios del github student developer pack).
      4. Al usar esa opción el coste del dominio debe ser gratis durante un año.
      5. Para gestionar el dominio acceda a http://controlpanel.tech/customer..

    Para el desarrollo de este enunciado y sus ejemplos se ha creado el dominio angoies.tech y se le ha asociado la IP elástica de la instancia EC2 de AWS. Además se han creado dos registros de tipo CNAME: whoami.angoies.tech y web.angoies.tech asociados a angoies.tech. Deberá hacer algo similar con su dominio.

    Otra opción es crear un dominio en Dynu (o Duckdns). En el caso de Dynu se parte de dominios de segundo nivel, por ejemplo freeddns.org. En ese caso el dominio creado podría ser clases.freeddns.org, y se le asocia la IP elástica de la instancia EC2 de AWS a ese dominio. Además se pueden crear registros de tipo CNAME: whoami.clases.freeddns.org y web.clases.freeddns.org asociados a clases.freeddns.org. De todas formas tanto Dynu como duckdns admiten wildcards en el dominio por lo que no haría falta crear los CNAMEs si apuntan todos a la misma IP.

    2. Traefik, Let's Encript y el servicio whoami¶

    En este apartado verá un primer ejemplo donde se expone el servicio de prueba whoami mediante https. Para ello necesitaría un certificado válido en el servidor whoami. Y como Traefik hace funciones de proxy inverso el certificado se instalará en Traefik.

    Let’s Encrypt es una Autoridad de Certificación gratuita, automatizada, y abierta. Si tiene acceso ssh a su servidor puede obtener un certificado utilizando el cliente que ellos propocionan. Como indican en su web:

    Recomendamos que la mayoría de las personas con acceso shell usen el cliente ACME llamado Certbot. Éste puede automatizar la emisión e instalación de certificados con cero tiempo de inactividad. También tiene modos de expertos para personas que no quieren autoconfiguración. Es fácil de usar, funciona en muchos sistemas operativos, y tiene documentación genial. Visita la página web de Certbot para conseguir instrucciones para tu sistema operativo y servidor de web.

    En el caso de Traefik el contenedor de traefik hace las funciones de cliente ACME y no se necesita usar el cliente Certbot. Y todoa la configuración se puede realizar en el fichero docker-compose.yml.

    2.1. Let's Encrypt en Traefik¶

    Para llegar a la solución final se darán tres pasos usando los ficheros traefik.vxX.yml (v1, v2 y v3).

    En el primer paso se configura traefik, el servicio whoami y SSL. En esta versión whoami sólo es accesible mediante https usando los certificados proporcionados por Let's Encrypt.

    Primero observe la configuración del servicio traefik donde se han añadido opciones respecto a ejemplos previos en ports, command y volumes

    services:
  traefik:
    image: "traefik:v3.3"
    command:
      - "--log.level=DEBUG"  # se incrementa el nivel de log
      - "--api.insecure=true"
      - "--providers.docker=true"
      - "--providers.docker.exposedbydefault=false"

      # Para SSL
      - "--entryPoints.websecure.address=:443"
      - "--certificatesresolvers.myresolver.acme.tlschallenge=true"
      # - "--certificatesresolvers.myresolver.acme.caserver=https://acme-staging-v02.api.letsencrypt.org/directory"
      - "--certificatesresolvers.myresolver.acme.email=profesor@midominio.com"
      - "--certificatesresolvers.myresolver.acme.storage=/letsencrypt/acme.json"

    ports:
      - "443:443"   # HTTPS 
      - "8080:8080" # The Web UI 
    volumes:
      # Volumen para certificado
      - "./letsencrypt:/letsencrypt"  
      - "/var/run/docker.sock:/var/run/docker.sock:ro"

    whoami:
      # omitido

    A continuación, se detalla el funcionamiento de esta configuración:

    2.1.1. Apartado command¶

    En este apartado es en el que se observan más cambios.

    En primer lugar opciones generales que no tienen que ver con el certificado:

    • --log.level=DEBUG: Activa el registro detallado para facilitar la depuración.
    • --api.insecure=true: Habilita el panel de control en el puerto 8080 sin autenticación, útil para pruebas (no recomendado en producción).
    • --providers.docker=true: Configura Traefik para detectar servicios mediante Docker.
    • --providers.docker.exposedbydefault=false: Obliga a etiquetar explícitamente los servicios que serán manejados por Traefik, mejorando la seguridad.

    Y las opciones relacionadas con el certificado:

    • --entryPoints.websecure.address=:443: Define el punto de entrada seguro (HTTPS) en el puerto 443. Este será utilizado por los servicios que necesitan certificados TLS.

    • --certificatesresolvers.myresolver.acme.tlschallenge=true: Activa el desafío TLS-ALPN para validar el dominio con Let's Encrypt. Este método requiere que el puerto 443 esté accesible desde Internet.

    • --certificatesresolvers.myresolver.acme.email=profsor@midominio.com: Correo electrónico registrado en Let's Encrypt para recibir notificaciones.

    • --certificatesresolvers.myresolver.acme.storage=/letsencrypt/acme.json: Define el archivo donde se almacenarán los certificados y datos relacionados de ACME. Es esencial que este archivo sea persistente.

    • La línea comentada --certificatesresolvers.myresolver.acme.caserver apunta al entorno de pruebas de Let's Encrypt. Esto es útil para evitar límites de emisión durante las pruebas.

    Tenga en cuenta que el nombre myresolver que se utiliza en estas opciones sera necesario luego en los servicios.

    2.1.2. Puertos mapeados¶

    • 443:443: Permite acceso HTTPS desde el exterior.
    • 8080:8080: Habilita el acceso al panel de control de Traefik.

    2.1.3. Volúmenes¶

    • ./letsencrypt:/letsencrypt: Persistencia de los datos de Let's Encrypt.
    • /var/run/docker.sock:/var/run/docker.sock: Permite a Traefik acceder al socket de Docker para detectar servicios.

    2.1.4. El servicio whoami¶

    Observe ahora la descripción del servicio whoami en el fichero traefik.v1.yml 

    services:

  traefik:
    # omitido

  whoami:
    image: "traefik/whoami"
    container_name: "simple-service"
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.whoami.rule=Host(`whoami.angoies.tech`)"
      - "traefik.http.routers.whoami.entrypoints=websecure"
      - "traefik.http.routers.whoami.tls.certresolver=myresolver"

    Las labels son la clave para indicarle a Traefik como manejar este servicio. Las primeras son genéricas: - traefik.enable=true: Habilita la integración de este servicio con Traefik. - traefik.http.routers.whoami.rule=Host(whoami.angoies.tech): Define una regla de enrutamiento basada en el host. Este servicio responderá a solicitudes dirigidas al dominio whoami.angoies.tech.

    Y las últimas son específicas de la configuración HTTPS:

    • traefik.http.routers.whoami.entrypoints=websecure: Asocia este servicio al punto de entrada HTTPS configurado (websecure).
    • traefik.http.routers.whoami.tls.certresolver=myresolver: Especifica que el certificado TLS para este servicio debe ser gestionado por el resolvedor myresolver. Recuerde que este nombre es el utilizado en la sección de command de traefik.

    2.2. Flujo de funcionamiento¶

    1. Inicio de Traefik:
    2. Traefik se inicia con la configuración especificada.

    3. Detecta servicios habilitados en Docker a través del socket y sus etiquetas.

    4. Configuración de HTTPS:

    5. Cuando un cliente accede a whoami.angoies.tech, Traefik usa el resolvedor myresolver para gestionar el certificado TLS.
    6. La primera vez que se accede Let's Encrypt valida el dominio mediante un desafío TLS, y si el desafio es superado emite un certificado automáticamente. El certificado se almacena en el fichero acme.json del volumen. En siguintes peticiones basta comprobar que el certificado almaceando sigue siendo válido.
    8. Redirección:
    9. Traefik recibe las solicitudes HTTPS en el puerto 443.
    10. Según la regla definida (Host) las redirige al contenedor whoami.

    2.3. Consideraciones adicionales¶

    • Seguridad:
    • La opción --api.insecure=true expone el panel de control sin autenticación. Es recomendable deshabilitarlo (--api=false) o protegerlo en producción.
    • Los volúmenes y configuraciones relacionadas con Let's Encrypt deben ser persistentes y estar protegidos adecuadamente.

    2.4. Prueba del primer escenario¶

    Basta hacer una petición con el comando curl para probar la conexión HTTPS al servicio whoami:

    curl https://whoami.angoies.tech
...

    3. Añadir un servidor web¶

    El segundo salto consite en añadir un segundo servicio a traefik que también use certificados. La configuración puede ampliarse fácilmente añadiendo servicios con etiquetas similares.

    En este caso (v2) se añade el servidor web nginx. 

    services:
  traefik:
    # omitido

  whoami:
    # omitido

  nginx:
    image: nginx:latest
    container_name: nginx_server
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.nginx.rule=Host(`web.angoies.tech`)"
      - "traefik.http.routers.nginx.entrypoints=websecure"
      - "traefik.http.routers.nginx.tls.certresolver=myresolver"

    Observe que las labels son similares a las del servicio whoami

    • se ha usado como nombre de ruta el nombre del servicio: zzz.routers.nginx.xxx=
    • se mantiene el nombre del resolver: xxx.certresolver=myresolver"
    • y no olvide modificar el Host, en este caso es web.angoies.tech

    3.1. Prueba¶

    Basta con hacer una petición con el comando curl y probar la conexión HTTPS:

    $ curl https://web.angoies.tech
...

    4. Redirección http a https¶

    Hasta este momento los servicios sólo admiten trafico HTTPS, y las peticiones HTTP no funcionan (también sería posible configurar el acceso HTTP por separado del acceso a HTTPS). Pero en este paso vamos a modificar la configuración para que se establezca una redirección automática de tráfico HTTP (puerto 80) a HTTPS (puerto 443). Esto mejora la seguridad de los servicios al garantizar que todas las conexiones se realicen mediante un canal cifrado.

    Estas serían las líneas a añadir en la sección command de traefik. Cada directiva en detalle:

    1. --entrypoints.web.address=:80

      Esta línea define un punto de entrada (entrypoint) para manejar las solicitudes entrantes en el puerto 80 (HTTP). Permite que Traefik reciba tráfico HTTP para gestionarlo o redirigirlo a HTTPS según las reglas configuradas.

    2. --entrypoints.web.http.redirections.entrypoint.to=websecure

      Esta directiva configura una redirección automática desde el punto de entrada web (HTTP) hacia el punto de entrada websecure (HTTPS). websecure es el punto de entrada configurado previamente para manejar solicitudes HTTPS en el puerto 443. Su funcionamiento: 1. Cuando un cliente realiza una solicitud HTTP en el puerto 80, Traefik detecta el tráfico y aplica esta regla de redirección. 2. La solicitud es reenviada al punto de entrada seguro (websecure), donde se cifra la conexión utilizando TLS.

    3. --entrypoints.web.http.redirections.entrypoint.scheme=https

      Esta opción complementa la anterior al especificar que el esquema utilizado en la redirección será HTTPS. - El esquema (http o https) define cómo se debe construir la nueva URL para el cliente redirigido. - En este caso, cualquier solicitud HTTP redirigida incluirá automáticamente https:// en lugar de http:// en la URL resultante.

      Por ejemplo: - Un cliente accede a http://whoami.angoies.tech. - Traefik genera una redirección a https://whoami.angoies.tech, cambiando el esquema y preservando el resto de la URL (ruta, parámetros, etc.).

    Flujo Completo de Redirección

    1. Un cliente realiza una solicitud a un servicio utilizando HTTP en el puerto 80.
    2. Traefik escucha en el puerto 80 mediante el entrypoint web.
    3. Detecta que debe redirigir esa solicitud a websecure.
    4. Genera una redirección 301 o 302 (según configuración predeterminada) hacia la misma URL, pero utilizando HTTPS.
    5. El cliente repite la solicitud al puerto 443 con una conexión cifrada.

    Ventajas de esta configuración

    1. Seguridad mejorada: Garantiza que todo el tráfico se realiza mediante HTTPS, protegiendo contra ataques como el "man-in-the-middle".
    2. Experiencia de usuario:Redirigir automáticamente elimina la necesidad de que los usuarios recuerden ingresar https:// manualmente en sus navegadores.
    3. Cumplimiento de estándares:Cumple con mejores prácticas y requisitos como los de SEO (Google prioriza sitios con HTTPS).

    Aviso: Compruebe que ya exista un entrypoint llamado websecure configurado para manejar el tráfico HTTPS (puerto 443) y asociado a un certificado TLS válido: 

    --entryPoints.websecure.address=:443
--entryPoints.websecure.http.tls=true

    4.1. Prueba¶

    Basta con hacer una petición con el comando curl y probar la conexión HTTPS. Para poder seguir la redireccion con curl debe usar la opción -L:

    $ curl http://whoami.angoies.tech
...
$ curl -L http://whoami.angoies.tech
...
$

    6. Anexos de ampliación¶

    6.1. desafío TLS-ALPN y el fichero acme.json¶

    El proceso para emitir un certificado TLS con Let's Encrypt utilizando el desafío TLS-ALPN-01 incluye varios pasos esenciales. Este método garantiza que solo el propietario del dominio pueda obtener el certificado correspondiente. A continuación, se detalla el flujo de trabajo:

    1. Inicio de la solicitud:

    2. Traefik actúa como cliente de ACME y realiza una solicitud al servidor de Let's Encrypt para obtener un certificado para el dominio configurado (en este caso, whoami.angoies.tech).

    3. Desafío TLS-ALPN-01:

    4. Let's Encrypt requiere que el solicitante demuestre control sobre el dominio.
    5. En este método, Traefik configura temporalmente un certificado especial en el puerto 443. Este certificado se genera para cumplir con los requisitos específicos del desafío TLS-ALPN-01.

    6. Let's Encrypt realiza una conexión directa al puerto 443 del dominio solicitado. Si la respuesta cumple con los datos esperados, se verifica que el solicitante controla el dominio.

    7. Emisión del certificado:

    8. Una vez validado el dominio, Let's Encrypt emite un certificado firmado.

    9. Este certificado incluye información como el nombre del dominio, su validez y la clave pública correspondiente.

    10. Renovación automática:

    11. Traefik maneja automáticamente la renovación del certificado antes de que caduque. El proceso de validación se repite de forma periódica.

    6.1.1. El papel del archivo acme.json¶

    El archivo acme.json juega un papel crucial en la gestión de los certificados emitidos por Let's Encrypt. Aquí se almacena toda la información necesaria para operar de manera segura y eficiente:

    1. Datos almacenados:
    2. Certificados TLS emitidos, incluyendo:
      • La clave privada asociada al certificado.
      • La cadena de certificación completa (incluyendo el certificado raíz y los intermedios).
    3. Tokens y configuraciones del protocolo ACME:
      • Información del desafío (como el token del TLS-ALPN-01).

    4. Estado y metadatos relacionados con las solicitudes ACME:

      • Últimos intentos de renovación.
      • Registros de errores (en caso de problemas de validación).

    5. Formato del archivo:

    6. El archivo está en formato JSON y se cifra para evitar accesos no autorizados. Traefik es responsable de gestionar su lectura y escritura.

    7. Persistencia del archivo:

    8. Es fundamental que acme.json se mantenga en un volumen persistente (como se define en el YAML con ./letsencrypt:/letsencrypt).
    9. Si el archivo se pierde, Traefik tendrá que reiniciar el proceso de validación desde cero, lo que puede causar interrupciones temporales.

    Para ver las fechas de renovación de los certificados puede ejecutar el comando jq 

    $ sudo jq -r '.myresolver.Certificates[] | "\(.domain.main) \(.certificate)"' acme.json | while read -r domain cert; do echo "Dominio: $domain";  echo "$cert" | base64 -d | openssl x509 -noout -startdate -enddate; echo "---------------------------"; done

    6.1.2. Importancia y buenas prácticas¶

    1. Seguridad:

    2. Dado que acme.json contiene claves privadas y datos sensibles, debe protegerse adecuadamente. Esto incluye restringir el acceso mediante permisos adecuados y evitar su exposición en entornos públicos.

    3. Rendimiento:

    4. Al reutilizar certificados almacenados en acme.json, se reduce la carga en el servidor de Let's Encrypt y se evita superar los límites de emisión.

    5. Diagnóstico y solución de problemas:

    6. Si hay problemas con la obtención o renovación de certificados, acme.json puede ser una fuente valiosa de información para investigar el problema. Y por supuesto docker log del servicio de traefik.

    6.1.3. Conexión entre el desafío y acme.json¶

    • Durante el desafío TLS-ALPN-01, los tokens generados por Let's Encrypt se almacenan temporalmente en memoria, pero los resultados de la validación y los certificados emitidos se guardan de manera permanente en acme.json.
    • Cada vez que Traefik inicia, lee el archivo acme.json para cargar los certificados existentes y evitar nuevas solicitudes innecesarias.
